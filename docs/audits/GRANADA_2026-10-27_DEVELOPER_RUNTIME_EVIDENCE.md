# Granada 2026-10-27 — Developer runtime error evidence, Windows + Android

## Existing capability and gap
Windows Developer already audits live WinForms controls, APO configuration and selected local properties, and captures verbatim owner annotations. Android Developer inspects real Compose anchors and checks audio/EQ state on demand. Neither previously kept a bounded, privacy-safe history of *observed* runtime failure states to inspect after a transient error resolved or the application restarted. #77 remains open.

## Implementation
**Android:** `DeveloperRuntimeLedger` is an explicitly bounded (16 categories, maximum 100000 occurrences), closed-vocabulary record of **actual AudioEngineUiState / EqualizerUiState transitions**: audio engine ERROR, EQ ERROR, boost percent outside contract, wrong seven-band EQ shape and nonfinite gains. Developer Compose observes the real state; events are deduplicated while a condition remains active and recorded again only after recovery and recurrence. Stored in separate Developer-package SharedPreferences under `runtime_incidents_v1`, never mixed with owner notes, Android public app, audio PCM, device IDs, user-controlled engine messages, exception text or credentials. Invalid/unreadable history is preserved and reported separately instead of overwritten. The real Developer inspector shows count; audit JSON and AI handoff include closed-code event counts and first/last timestamps.

**Windows:** `DeveloperRuntimeEvidence` uses a separate private Developer data file with atomic writes and allowlisted codes for observed startup exception and Developer notes/report save failure paths. It never stores actual exception text, stack traces, filesystem paths, user comments, audio PCM or endpoint identifiers. Existing catch handlers retain their behavior; the fault recorder cannot mask the original failure. Read-only Developer RunAudit now includes recorded event counts, first/last UTC and an explicit error if metadata is corrupted; ordinary public LouderMe never accesses this file. `--check-developer-contract` exercises real JSON roundtrip, duplicate count, corrupted-file preservation, failure isolation and rejection of unapproved free text.

**Regression and boundaries:** Android JVM tests exercise real state classification, dedup/persistence contract, bounded JSON, reject malicious/unapproved runtime text. Windows exact-head developer contract builds/runs on Windows CI; Android actual installation, Home/About and Developer persistence runs in Android CI. Device audio is neither installed nor acoustically validated, and code **does not claim system-wide gain**. No public signing or release, and no new version. Public stable Windows 0.1.17 and Android 0.1.12 unchanged. This telemetry covers the listed error states and three Windows caught-fault paths, **not every possible crash, GPU renderer fault, background service error or unobserved task exception**.

## Merge gate
CI must finish successfully for Windows real installed application and standalone Developer smoke, Android installed app/Developer persistence. Inspect any failures and fix exact source before merging. Do not relabel failure state or auto-publish a stable release.
